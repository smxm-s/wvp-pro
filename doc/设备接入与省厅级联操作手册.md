## 1. 名词与角色

| 名词 | 含义 | 在平台里的位置 |
|---|---|---|
| **设备** | 物理盒子（NVR / 摄像机 IPC / 执法记录仪），做 SIP 注册的主体 | 【国标设备】列表 |
| **通道** | 设备上对外提供的一路画面（NVR 下挂 1~N 路） | 【通道列表】 |
| **目录（Catalog）** | 平台向设备"要通道清单"的协议动作，通道靠它被发现 | 设备列表「订阅 → 目录」 |
| **本平台** | 你部署的 WVP-PRO，对下是上级、对上是下级 | 本项目 |
| **上级平台（省厅）** | 你推送视频过去的目标平台 | 【国标级联】 |
| **共享目录 + 按需拉流** | 级联的核心机制：只共享通道清单，省厅点播时才去拉流 | 级联 + 通道共享 |

**三条独立链路**（务必区分，排障时按链路定位）：

```
链路①  下级设备  ──GB28181注册/推流──▶  本平台        （接入）
链路②  本平台    ──RTSP/HTTP/GB28181──▶  浏览器      （本地观看）
链路③  本平台    ──GB28181级联/转发──▶  省厅平台      （上报）
```

## 2. 开工前检查清单（前置条件）

> ⚠️ **本节不过关，后面所有步骤都会失败。请先逐项打勾。**

### 2.1 部署形态（最重要）

| 项 | 要求 | 说明 |
|---|---|---|
| ☐ | WVP 与 ZLM（媒体服务器）部署在**同一台有固定公网 IP 的服务器**上 | 学习阶段用的「本机 WVP + SSH 反向隧道 + 云端 ZLM」**不能用于生产**，隧道断了设备就掉线 |
| ☐ | 平台对外 IP 固定不变 | IP 变一次，所有设备都要改配置 |
| ☐ | 已做 **NTP 时间同步** | 设备和平台时间差超过几分钟 → 注册失败、录像查不到 |

### 2.2 网络与端口（在服务器安全组/防火墙放通）

| 端口 | 协议 | 用途 | 谁能访问 |
|---|---|---|---|
| 8116 | **UDP + TCP** | SIP 信令（设备注册、平台级联） | 下级设备、省厅平台 |
| 30000-30500 | UDP | 接收下级设备的 RTP 媒体流 | 下级设备 |
| **50000-55000** | UDP | **向省厅发送 RTP 媒体流** | 省厅平台 |
| 80（或 8080） | TCP | ZLM HTTP / FLV、HLS 拉流 | 浏览器、省厅 |
| 554 / 1935 | TCP | ZLM RTSP / RTMP | 浏览器、省厅 |
| 18080 | TCP | 平台 Web 界面 | 运维人员 |

### 2.3 账号与凭据

| 项 | 位置 | 本环境当前值（示例） |
|---|---|---|
| 平台管理账号 | 平台登录页 | `admin` |
| 数据库 | `application-dev.yml` → `spring.datasource` | `124.221.154.16:3307` / `wvp_local` |
| Redis | `application-dev.yml` → `spring.data.redis` | `124.221.154.16:6380` / db `7` |

### 2.4 资料申请（提前发起，等待时间长）

| ☐ | 向省厅索取《上级平台接入信息表》（见[附录 C](#附录-c省厅对接信息需求表)） |
|---|---|
| ☐ | 确认省厅要求：编号**由省厅分配**还是**自行编制后备案** |
| ☐ | 确认园区摄像头/记录仪型号，是否支持 GB/T 28181 |

## 4. 第一步：编号规划

### 4.1 GB28181 编号规则（20 位）

```
┌────── 前 10 位：域 ──────┐┌─3位─┐┌── 7 位 ──┐
  41010500        00         200    0000001
  └─ 8位行政区划码 ─┘ └2位行业┘  类型    序号
```

| 位置 | 含义 | 取值 |
|---|---|---|
| 第 1-8 位 | 行政区划码（GB/T 2260） | 你园区所在区县，**必须准确** |
| 第 9-10 位 | 行业编码 | 视频监控/公安常用 `00` |
| 第 11-13 位 | 类型 | `200`=平台、`215`/`216`=分组/虚拟组织、`132`=前端设备（摄像机/NVR） |
| 第 14-20 位 | 序号 | 顺序编号 |

### 4.2 本项目的编号分配方案（示例，按实际替换行政区划）

假设园区位于 **XX 省 XX 市 XX 区（行政区划码 `XXXXXXXX`）**：

| 对象 | 编号 | 说明 |
|---|---|---|
| 本平台 | `XXXXXXXX` + `00` + `200` + `0000001` | 即 SIP ID，与 `sip.id` 一致 |
| 域 | `XXXXXXXX` + `00` | 与 `sip.domain` 一致 |
| 园区摄像头（前端设备） | `XXXXXXXX` + `00` + `132` + `0000001` 起 | 一台设备一个号 |
| 执法记录仪 | `XXXXXXXX` + `00` + `132` + `0000100` 起 | **单独起一段，便于识别** |

### 4.3 编号规划表模板（建议打印/填好后下发到现场）

| 序号 | 园区/区域 | 设备类型 | 品牌型号 | 安装位置 | **设备编号** | **通道编号段** | 备注 |
|---|---|---|---|---|---|---|---|
| 1 | 办公区 | NVR | 海康 DS-8632N | 弱电间 | `...1320000001` | `...1320000011`~`...1320000014` | 4 路 |
| 2 | 大厅 | IPC | 大华 DH-IPC | 大厅吊顶 | `...1320000002` | `...1320000021` | 1 路 |
| 3 | 门岗 | 执法记录仪 | — | 保安随身 | `...1320000100` | `...1320000101` | 4G 回传 |

> **规则**
> 1. 编号一旦定稿，**在整个对接周期内不要修改**；
> 2. 省厅若要求「编号需报备」，则**以省厅给定的编号为准**，不要自行编制；
> 3. 同一个省厅下**不要出现重复的域**。

## 5. 第二步：批量接入园区摄像头

### 5.1 设备侧配置（各品牌路径速查）

| 品牌 | 配置路径 |
|---|---|
| 海康（NVR/IPC） | 配置 → 网络 → 高级配置 → **平台接入 → GB28181** |
| 大华 | 设置 → 网络设置 → 平台接入 → **GB28181** |
| 宇视 | 配置 → 网络 → 平台对接 → **GB28181** |
| 通用/其他 | 找「**GB28181**」「**28181**」「**国标接入**」字样 |

**填写内容（照抄第 3 节）：**

| 设备侧字段 | 填什么 |
|---|---|
| 启用 | ✅ 勾选 |
| SIP 服务器 ID | `41010500002000000001` |
| SIP 服务器域 | `4101050000` |
| SIP 服务器地址 | `124.221.154.16` |
| SIP 服务器端口 | `8116` |
| SIP 用户名 / 设备编号 | 该设备自己的编号，如 `41010500001320000001` |
| 注册密码 / 认证密码 | `12345678` |
| 通道编号 | `...1320000011` 起（部分设备自动生成） |
| 注册有效期 | `3600` 秒 |
| 心跳周期 | `60` 秒 |
| 传输协议 | **TCP**（公网/4G 场景强烈建议 TCP） |

### 5.2 平台侧验证（设备上报后）

进入 **设备接入 → 国标设备**：

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 观察列表 | 出现设备行，状态 **在线**；离线则见[第 9 节](#9-故障排查速查表) |
| 2 | 「订阅」列勾选 **目录** | 平台向设备发起目录查询，并周期性同步 |
| 3 | 点该行「**通道**」按钮 | 弹出该设备下的通道列表 |
| 4 | 进入 **通道列表** 菜单 | 出现该设备的全部通道，状态应与其设备一致 |

> **关键认知**
> - 注册成功只让**设备**出现在列表；**通道**要靠「目录订阅」才会出现；
> - 通道的在线状态**来自设备目录里的 Status 字段**，设备掉线 → 其所有通道一并变 OFF；
> - 「订阅」列还有 **位置**、**报警**：执法记录仪建议一并勾选（见第 6 节）。

### 5.3 通道业务属性设置（必做）

通道进来后是"裸数据"，需要补业务属性。**这些属性只有平台侧才有**，是后续权限隔离和级联的基础。

| 属性 | 在哪设 | 作用 |
|---|---|---|
| 行政区划（civilCode） | 通道 → 编辑 / 批量设置 | **数据区域隔离**依据 |
| 业务分组 | 【业务分组】菜单 | 级联时的目录结构 |
| 点位经纬度 | 通道 → 编辑 | 电子地图自动落点 |
| 录像计划 | 【录制计划】菜单 | 平台侧录像 |

**批量接入建议流程**：

```
① 先接 1 台设备跑通「注册 → 目录 → 播放」闭环
② 按编号规划表批量配置其余设备
③ 统一设置通道的行政区划与业务分组
④ 给需要的通道挂录像计划
```

### 5.4 快速自检

| 检查项 | 方法 |
|---|---|
| 设备在线 | 国标设备列表状态列 |
| 通道可见 | 通道列表能查到该设备编号前缀的通道 |
| 能播放 | 【分屏监控】选通道 → 出画面 |
| 能录像 | 配了录像计划后，【云端录像】能回看 |

## 6. 第三步：接入执法记录仪

### 6.1 先判定类型（决定走哪条链路）

| 类型 | 判定方法 | 走哪条路 |
|---|---|---|
| **支持 GB/T 28181** | 说明书/菜单里有「GB28181」「国标」 | 按 **第 5 节** 接入，**与摄像头完全一致** |
| **仅支持 JT/T 1078（部标）** | 说明书只提「1078」「部标」「JT/T 1078」 | 走平台【部标设备】菜单，**需额外配置 1078 流媒体服务** |

> **建议优先采购支持 GB28181 的记录仪**，两条链路混用会明显增加排障成本。

### 6.2 走 GB28181 的记录仪

配置方式与第 5 节完全相同，差异只有三点：

| 差异点 | 说明 |
|---|---|
| 编号段 | 建议单独起一段（如 `...1320000100` 起），便于识别与权限划分 |
| 传输协议 | 必须 **TCP**（走 4G/5G 公网，UDP 易丢包） |
| 订阅 | 建议同时勾选 **目录 + 位置 + 报警**，否则拿不到定位与报警 |

**记录仪的固有特性（不是故障）**：

- 频繁上下线（开关机、信号抖动）→ 列表里"时有时无"是正常的；
- 判断是否配错，只看两点：**能否稳定注册上** + **目录订阅能否拉到通道**。

### 6.3 走 JT/T 1078 的记录仪（如确有）

1. 确认 ZLM 已开启 1078 支持；
2. 在平台 **部标设备（JT1078）** 菜单按终端信息注册：
   - 终端手机号（SIM 号）
   - 车牌号 / 车牌颜色
   - 终端厂商 ID / 终端型号
3. 接入后在【通道列表】同样以通道形式呈现，观看方式与国标设备一致。

## 8. 第五步：推送视频到省厅（国标级联）

> **核心机制**：不是把流一直推给省厅，而是 **共享通道目录 + 省厅点播时按需转发**。

### 8.1 向省厅索取信息

用[附录 C](#附录-c省厅对接信息需求表) 的表格向省厅索取，拿到后填入下表。

### 8.2 在平台新增上级平台

**操作路径：左侧菜单【国标级联】→ 新增**

| 表单字段 | 填什么 | 来源 |
|---|---|---|
| 名称 | 省厅平台（自定义） | 自定 |
| **SIP 服务国标编码** | 省厅的平台编号，如 `41000000002000000001` | **省厅给** |
| **SIP 服务国标域** | 省厅的域，如 `4100000000` | **省厅给** |
| **SIP 服务 IP** | 省厅接入 IP | **省厅给** |
| **SIP 服务端口** | 省厅接入端口，如 `5060` | **省厅给** |
| **设备国标编号** | **本平台的编号** `41010500002000000001` | 见第 3 节 |
| 本地 IP / 本地端口 | 留空，或按省厅要求 | — |
| SIP 认证用户名 | 省厅分配的账号（常为本平台编号） | **省厅给** |
| SIP 认证密码 | 省厅分配的密码 | **省厅给** |
| 注册周期 / 心跳周期 | `3600` / `60` | 默认 |
| 信令传输 | TCP | 公网建议 TCP |
| 字符集 | `GB2312` | 按省厅要求 |
| 行政区划 | 本平台所属行政区划 | 按省厅要求 |
| 平台厂商 / 型号 / 安装地址 | 如实填写 | — |
| **启用** | ✅ | |
| **主动推送通道** | ✅ | 自动把通道目录推给省厅 |
| 推送平台信息 / 推送分组信息 / 推送行政区划 | 按省厅要求勾选 | — |
| RTCP 保活 | 按省厅要求 | — |

### 8.3 验证注册成功

保存后回到【国标级联】列表：

| 检查项 | 预期 |
|---|---|
| 状态列 | 变为 **在线**（表示本平台已成功注册到省厅） |
| 通道数 | 显示可共享的通道数量 |

> 状态长期"离线" → 检查：网络是否可达省厅 IP:端口、SIP 认证账号密码是否正确、信令传输协议是否与省厅一致。

### 8.4 通道共享（决定省厅能看到哪些通道）

**操作路径：【国标级联】→ 该平台的「通道共享」→ 选择「未共享」标签页 → 勾选通道 → 确定**

| 要点 | 说明 |
|---|---|
| 权限控制 | **没勾选的通道，省厅完全看不到**——敏感染控就靠这里 |
| 分组推送 | 按业务分组/行政区划推送，目录结构更清晰 |
| 编号不变 | 省厅看到的通道编号 = 本平台通道编号，**严禁后期修改** |

### 8.5 与省厅联调

按以下顺序联调，逐层定位问题：

```
① 级联状态 = 在线        → 信令通了
② 省厅侧能看到通道目录    → 目录共享成功
③ 省厅点播单个通道出画面  → 媒体转发通了（重点查 50000-55000 端口段）
④ 全量通道抽查若干路      → 批量通过
```

### 8.6 级联三条铁律

1. **只有点播时才拉流**，不要做成常推，否则专线会被打满；
2. **通道编号推给省厅后不要再改**，改了省厅会当成新通道，录像与共享关系全部错位；
3. **改本平台 SIP ID / 域 = 在省厅侧换了个平台**，必须重新报备并重做级联。

## 9. 故障排查速查表

| 现象 | 可能原因 | 排查动作 |
|---|---|---|
| 设备一直离线 | 时间未同步 / 8116 未放通 / 密码不一致 / NAT 未映射 | 校时；`telnet 平台IP 8116`；核对密码；检查路由 NAT |
| 设备在线但**通道为空** | 未做目录订阅 / 设备不主动通知 | 设备列表勾选「目录」订阅，等待同步 |
| 通道状态一直 OFF | 设备已离线 | 先修设备在线，通道状态随之恢复 |
| 播放黑屏（本地） | RTP 30000-30500 未放通 / sdp-ip 配错 / ZLM secret 不匹配 | 放通端口；核对 `sdp-ip`；核对 secret 与 `hook.admin_params` |
| 级联状态离线 | 认证错误 / 网络不通 / 协议不一致 | 核对省厅给的账号密码与 TCP/UDP；测通省厅 IP:端口 |
| 级联在线但省厅无目录 | 未勾「主动推送通道」/ 未做通道共享 | 补勾选项；到「通道共享」页推送 |
| 省厅点播黑屏 | **50000-55000 未放通** / 本平台到设备的流没起来 | 放通级联端口段；**先在本平台单独点播验证**再看级联 |
| 记录仪时有时无 | 4G 信号/开关机 | 属正常现象，关注能否稳定注册 |
| 通道编号重复 | 多园区共用一个域 | 按第 4 节重新分配域与序号 |
